## 📖 About
This repository provides a fully automated, distro-agnostic workflow to compile the `shadps4` emulator (via the [bigmak94/AstroQuest](https://github.com/bigmak94/AstroQuest) project) and package it into a portable Linux AppImage. 

It includes three scripts designed to work together:
1. `build-everything.sh`: The master script that checks dependencies, clones the source, compiles `shadps4`, and triggers the AppImage build.
2. `build-appimage.sh`: Collects dependencies, sets up the AppDir, and packages everything using `linuxdeploy` and `appimagetool`.
3. `astroquest-linux-v2.sh`: A robust, GUI/TTY-friendly launcher that handles settings, game discovery, `.pkg` unpacking, and OpenXR environment setup.

## 🚀 How to Compile

### Option A: Standard Build (AppImage *without* the game)
This is the recommended method for sharing or publishing. The resulting AppImage will be small and will prompt you to select your game folder on first launch.

    # 1. Clone this repository
    git clone https://github.com/YOUR_USERNAME/astroquest-linux-scripts.git
    cd astroquest-linux-scripts

    # 2. Make the master script executable
    chmod +x build-everything.sh

    # 3. Run the script (leave the game path empty when prompted)
    ./build-everything.sh

### Option B: Bundled Build (AppImage *with* the game inside)
If you are building this strictly for **your own personal use**, you can bundle the game directly into the AppImage. 

**💡 The Space-Saving Advantage:**  
A raw dumped game folder (`CUSA12392`) takes up about **~13 GB** of disk space. However, when you pass the `GAME_DIR` variable to the build script, `build-appimage.sh` uses `zstd` compression (`--comp zstd`). This compresses the 13 GB of game data down to roughly **~6.6 GB** inside the final AppImage. This saves nearly 50% of disk space while maintaining lightning-fast decompression on the fly during gameplay!

    # Run the script and provide the path to your game folder when prompted
    # (The folder must contain 'eboot.bin')
    ./build-everything.sh
    # > Path to game directory: /path/to/your/CUSA12392

*Alternatively, you can pass it via environment variable:*  
`GAME_DIR=/path/to/your/CUSA12392 ./build-everything.sh`

## 🎮 How to Play

1. **Set up your OpenXR Runtime**: Ensure you have an OpenXR runtime installed and set as active (e.g., **WiVRn** or **Monado**). The launcher will warn you if none is detected.
2. **Connect your Controller**: Plug in or pair your PS5 DualSense (or DualShock 4) to your **PC**, *not* the headset. 
3. **Run the AppImage**:

        chmod +x AstroQuest-x86_64.AppImage
        ./AstroQuest-x86_64.AppImage

   *(If your system complains about FUSE, run it with: `APPIMAGE_EXTRACT_AND_RUN=1 ./AstroQuest-x86_64.AppImage`)*
4. **First Launch**: If you didn't bundle the game, a GUI or terminal prompt will ask you to select the folder containing your `eboot.bin` or `.pkg` file. If you provide a `.pkg`, the launcher will automatically unpack it for you.
5. **Settings Menu**: A settings window will appear allowing you to configure resolution, framerate, FOV, and desktop spectator view. These settings are saved to `~/.config/AstroQuest/settings.txt`.

| Script | Description |
| :--- | :--- |
| `build-everything.sh` | The all-in-one entry point. Validates dependencies, clones `bigmak94/AstroQuest` with submodules, compiles `shadps4` using `clang`/`ninja`, and calls the AppImage builder. |

## ⚠️ Troubleshooting
- **"No OpenXR runtime found"**: The game will still launch, but only in flat desktop mode. Install and configure [WiVRn](https://github.com/WiVRn/WiVRn) or Monado for VR.
- **Emulator crashes on start**: The launcher will warn you if `vm.max_map_count` is too low. Fix it temporarily with: `sudo sysctl -w vm.max_map_count=2147483642`
- **Long path errors (Proton/Wine)**: If using the Windows build via Proton, ensure the game folder path is under ~110 characters to avoid Windows API path length limits.
